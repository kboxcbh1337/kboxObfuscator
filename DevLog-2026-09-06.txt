## 二、HTML UI 浏览无法打开的修复

文件：`kbox-gui/src/main/java/com/kbox/gui/ProtectorGui.java`

1. **根因（真实 bug）**：HTTP 线程池用 `Executors.newCachedThreadPool`（corePoolSize=0）。UI 空闲 >60s 无任何请求时全部 worker 被回收 → 无非 daemon 线程 → JVM 退出 → 浏览器/页面再也打不开。
   修复：改为 `newFixedThreadPool(4)`，常驻非 daemon worker 保活。

2. **浏览器无法自动打开**：`Desktop.browse` 在受限/无桌面会话下静默失败（原实现只打印一行手动 URL）。
   修复：`openBrowser` 多级兜底链 —— `Desktop.browse` → Windows `rundll32 url.dll,FileProtocolHandler` / `cmd /c start` → macOS `open` → Linux `xdg-open` → 全失败才打印手动 URL。

验证：`GET /` → 200；服务空闲保持可访问。

## 四、混淆速度深度优化（CF 并行化）

文件：`ControlFlowObfuscator.java`、`ClassGraph.java`。

- 背景：字符串/常量/类型混淆等 per-class pass 早已经 `ParallelClassProcessor` 并行（threads=0 即 auto=CPU 核）；**控制流（CF）是最后一个仍单核跑的重型 pass**（对 CF3 大 jar 常占几分钟到几十分钟）。
- CF 并行化：`obfuscate()` 在类数 >8 时改走 `ParallelClassProcessor.processAll`（每类独立改写，graph/config 只读）；`parallelThreads=0`（默认）自动按 CPU 核数，`1` 强制原确定性串行路径，`N` 固定线程池。per-class 回滚与 neverFail 语义保留，protect 类一律 `markCfModified` 保证 frames 重算。
- `ClassGraph.cfModifiedClasses` 由 `HashSet` 改为 `ConcurrentHashMap.newKeySet()`（并行 mark 线程安全）。

实测（kbox-core-1.0.0.jar，203 类，CF strength=3，24 核）：
- 串行（parallelThreads=1）：**421.7s**
- 并行（默认 auto）：**59.5s** → 约 **7.1× 加速**；产物均正常生成。

## 五、混淆阶段全并行化（补全剩余 per-class pass）

背景：字符串/常量/类型混淆 + CF 已并行；本批把其余**逐类独立**的 pass 全部接入 `ParallelClassProcessor`（`parallelThreads`：0=auto 核、1=强制串行、N=固定池），并逐个做线程安全处理：

| Pass | 文件 | 处理 |
|---|---|---|
| 注解擦除 | AnnotationEraser | 直接 processAll |
| 调试信息伪造 | DebugInfoForger | processAll + 原子计数 |
| 异常跳转 | ExceptionJumpObfuscator | carrier 已前置注入 → processAll |
| 空值守卫 | ResourceNullGuardTransformer | processAll + 原子计数 |
| 方法内联/抽取 | MethodObfuscator | 两遍分别 processAll |
| 调用图隐藏 | CallGraphHider | decoy 合成类改为**并行前**注入，再 processAll bait |
| 反射门 | ReflectionGateInjector | holder 前置已建 → processAll |
| Kotlin @Metadata | KotlinMetadataFixer | processAll + fixedClasses 改 AtomicInteger |

保守保留串行并注明原因：`StringScatterer`（跨类共享字段分配）、`NameObfuscator.compute`（全局 union-find）、`AutoKeepDeriver`、`JnicOrchestrator`、`BfvmMethodInjector`（编译链共享静态态）、`AntiDecompiler/Watermarker/Honeypot`（非逐类，合成类注入）。

实测：204 类 CF3 段耗时从早期单核路径的 ~400s+ 量级压缩到并行 48.9s（24 核）。
